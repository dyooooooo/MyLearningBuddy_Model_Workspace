## 三、两处做过可执行验证的指控

### 3.1 第 11 条：行内图颠倒（证实，金样已钉死）

`render-page.mjs:98`：

```js
const body = `${extras}${inner}`.trim();
```

而 `:196-202` 构造 extras 时，prevOk 分支用的是**追加**语义：

```js
if (prevOk) {
  extras[i - 1] = `${extras[i - 1] || ""}${img}`;   // 意图：接在前一段的段尾
} else if (nextOk) {
  extras[i + 1] = `${img}${extras[i + 1] || ""}`;   // 意图：接在后一段的段首
}
```

`paragraph()` 一律前置 → **prevOk 分支的意图与实现相反**，nextOk 分支才对。

金样证实。`tests/goldens/cols-box.in.json` 的块序：

```
deco(0) → h1(1) → p1(2, text) → icon(3, inline_image) → flow(4) → box(5) → q1(6) → goal(7)
```

`icon` 紧跟在 `p1` 之后 → 命中 prevOk → 应接在「通过图 1-13 了解过程。」**之后**。而 `tests/goldens/cols-box.out.html` 的实际输出：

```html
<p data-kb-block="p1"><img class="kb-ir-inline" src="…/icon.jpg" alt="图">通过图 1-13 了解过程。</p>
```

图在文前。**错误已被金样固化为「正确」**，修代码必须同步改这份金样，否则测试会红。

### 3.2 网关编码穿越（证实可利用，原报告低估）

`exam-ocr-server/app/kb/routes.py:327`：

```python
if path == "ir" or path.startswith("ir/") or path.startswith("ir?"):
    return await proxy_agent(path, request)
```

`proxy_agent` 里 `url = f"{base}/v1/{path}"`，`path` 无任何归一化或白名单校验。

实测一（Starlette 是否把编码穿越解进 path 参数）：

```
GET /proxy/%2e%2e%2fsecret            → path 参数 = "../secret"
GET /proxy/%2E%2E%2F%2E%2E%2Fsecret   → path 参数 = "../../secret"
GET /proxy/ir%2F..%2F..%2Fsecret      → path 参数 = "ir/../../secret"
```

实测二（httpx 是否归一化掉 `..`）：

```
http://agent/v1/../secret         → 实际请求路径 /secret
http://agent/v1/../../secret      → 实际请求路径 /secret
http://agent/v1/ir/../../secret   → 实际请求路径 /secret
```

**后果**：`proxy_kb` 里那份 `ir / books / events / library` 白名单可被绕过；而 `proxy_agent` 转发时**自带 agent 令牌**（`_agent_auth_headers()`），等于把调用方**提权到 agent 的全部路由**，包括 `POST /v1/surfaces/{slot}/paint`——正好是第 12 条的 XSS 汇点。两条问题**可组合**：穿越打到 paint，把未消毒的 `table_html` 直接送进 kb-ui 的 DOM。

原报告把这条放在**它自己的** §三「待确认」，只写了「编码穿越原样透传」，没有验证 httpx 归一化这一步，也没有点出提权与组合效应。**建议升格，并排在修复顺序第 1 位。**

未核实：`proxy_kb` 自身是否还挂了 C2 侧鉴权（读取该处的命令被审批系统挡下，未绕行）。挂了的后果是「任何持 C2 令牌的局域网用户 → agent 全权」，没挂是「匿名可打」。**建议按后者设防。**

附带：`:283 events?`、`:327 ir?`、`:330 books?` 三处 `startswith("…?")` 按 Starlette 路由匹配语义（query string 不进 path 参数）应为死代码。此条为**推理，未实测**。

03:16 的重构把渲染收进新文件 `kb-ui/src/pagePane.ts`，`loadPage` 现在在 await **之前**捕获 `activeId` 并作为参数传下去（`irLibrary.ts:279`）——原报告指的第一处（「await 后裸读 activeId 把新书 blocks 填进旧书 shell」）**已缓解**。

残留三处：
