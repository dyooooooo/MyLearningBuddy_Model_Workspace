# 图信息提取与块合并 —— 改进建议（说人话版）

2026-09-16。起因：三张「原书 vs 算法 HTML」对照截图（化学 13 轨道图、化学 13 化学史话、数学 11），用户提出两个问题：图信息提取不完整（重复 + 漏）、嵌套完成后块太多需要合并整合。本文是对着实际数据查证后的结论和建议。

---

## 查证结果

### 问题一的根子：算法分对了，旧账没洗

- `pages/algo-chem-0013.json` 的图带是**对的**：4 个面板，（a）贴面板 0、（b）贴面板 2、共享题注「图1.5　原子轨道的空间伸展方向」单独一条，无重复。
- 重复出在 `paint-chem-0013.json` 的块 4：题注是「（b）p 轨道图1.5　原子轨道的空间伸展方向」——**源数据（MinerU）里这句本来就是粘错的**。
- 渲染规矩「空题注不覆盖」（`_set_caption` 遇空 return）只防了覆盖好题注，没防留着坏题注：算法判该面板无说明 → 跳过 → 源数据粘错的旧题注永远洗不掉 → 页面上「图1.5」出现两遍。
- 四张图算法全部抓到、地址都在（块 1–4 各有一个 src hash）。截图里的灰框 = 图片文件没取到（资源仓库/解析问题），不是提取问题。
- 附带：化学史话的书本图标是页上第 5 张图（块 7），没进面板行，属装饰小图，走 icon 逻辑。

### 问题二的现状：块照搬 MinerU 的切法

- 数学 11 页 27 个块（23 文本），每段一句一块。练习题四小题是块 4–7，**存储顺序是 (1)(3)(2)(4)**（先左列后右列），阅读序错误藏在碎块里。
- 嵌套完成时每个格子的段落已有顺序和角色标签（title/text、缩进级、对齐），合并所需信息齐全。

## 建议

### 问题一：图

1. **「空的不写」改成「空的就清空」**：算法判定面板无说明时，把源数据的旧题注清掉，不保留。（`_set_caption` 一行改动）
2. **算法结论是唯一答案**：图的提取到出 HTML 只信算法整合后的结论（几张图、哪句贴哪张、哪句整行），源数据只当候选材料。
3. 灰框去核对图片仓库（asset key 是否存在/能解析），与提取逻辑无关。

### 问题二：块合并

1. **树别动，改装字**。在渲染步（render.py `to_ir_page`）写块之前，把同一格子里连续段落装进一个块，段首带角色标记（markdown 最省事：`##` 标题、`###` 子标题、普通行正文，缩进级可放标记或属性）。数学 11 预计 27 → 6~8 块。
2. **红线**：左右栏不并、图不并、跨页不并。
3. **顺手修阅读序**：合并时按人读的顺序排字，把练习题的 (1)(3)(2)(4) 排成 (1)(2)(3)(4)。
4. **代价：坐标**。块合并后段级 bbox 丢失，若要「点段落高亮原图」，须在块内每段标记后保留原 bbox，不能只存纯文字。
5. 附带小项：数学页公式显示成 `\frac{1}{2}` 原文是预览端没渲染 LaTeX，文本里 `$…$` 标记齐全，内容没丢。

### 优先级

1. 空题注清空（一行级，立刻见效）
2. 核对灰框图片资源
3. 渲染层合并器（树不动，可独立做、独立验证）
