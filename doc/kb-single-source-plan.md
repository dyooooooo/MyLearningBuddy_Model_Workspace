# 知识库正文层：从「双写文件」走向「单一源 + 派生缓存」

> 状态：**三步都已落地**（第三步 2026-09-09）
> 日期：2026-09-09
> 关联：`doc/kb-platform-topology.md`（D1 条目）、`doc/mineru-fullbook-import-flow.md`

---

## 0. 一句话结论

`mid/*.md`（中间文件）现在有**两个互斥的身份**——它既是"从正文算出来的产物"，又是"可以被人和 Agent 直接编辑的记录文件"。同步的难，全部来自这一处身份混淆。

业界成熟做法是把这两个身份拆开：**正文只保留一份，呈现是纯函数产物（可随时丢弃重建），需要人工干预的注解用稳定锚点旁挂**。

关键结论是：**你想注入的 Obsidian 特性（双链、区块、属性、标签），恰好一个都不需要中间文件。** 详见 §2.3。

## 1. 实际情况

### 1.1 现在这两层各是什么

| 文件 | 角色 | 谁在写 |
|---|---|---|
| `pages/NNNN.md` | 官方正文，AI 抽取的输入 | 导入流水线、人工编辑（`page_sync` **不再写**） |
| `mid/NNNN.md` | 正文 + `::: kb-*` 呈现围栏 | `page_sync` 按正文重贴、Agent 改、人工改 |
| `mid/.stamps/NNNN.json` | 缓存键（正文 sha + 中间层 sha） | `page_sync.write_stamp()` |

设计本意（你说的那个）是对的：**显示归显示、抽取归抽取**。问题不在这个意图，在于把"显示层"实现成了**第二份可写的全文副本**。

### 1.2 三条会损坏数据的路径（第一步已拆掉写回）

`_write_source()` 已删除。当前：中间层单边改字 → `conflict` + `mid/NNNN.md.conflict`；只差空行 → `stamp_layout`；两边都变 → 正文赢、重贴中间层。下面是改之前的路径，留着对照。

**路径一 · 中间层单边变更 → 直接覆盖正文（已删）**

```python
if mid_dirty and not src_dirty:
    _write_source(sid, n, strip_skin(mid))    # 已不存在
    return _done("write_source")
```

**路径二 · 两边都变 → 比文件修改时间，平局判中间层赢（已删）**

```python
mid_newer = _mtime(mid_file) >= _mtime(source_path)
if mid_newer:
    _write_source(sid, n, strip_skin(mid))
```

同一秒内两边都被改（脚本批处理时很常见）时间戳会相等，`>=` 让中间层无条件获胜。上次那个实验里人工订正被自动标注吃掉，就是走的这条。

**路径三 · 围栏用"被围的那段原文"当锚点，正文一改就脱锚，然后静默丢弃**
`page_sync.py:235-265`（`paste_fences` → `_find_block`）

```python
needle = page_bytes(inner).rstrip("\n")     # 拿围栏里的整段文字当锚点
pos = _find_block(source, needle)           # 去新正文里做整块字符串匹配
if pos < 0:
    event("sync.fence_drop", ...)           # 找不到就记一笔
    continue                                # 然后这个围栏就没了
```

这条最值得说：**这套系统事实上已经是 standoff（旁挂）注解了**——围栏是注解，正文是被注解对象。但它选的锚点是"被注解的那段文字本身"。正文改一个标点，注解就找不到家，`continue` 掉，呈现效果无声消失。

### 1.3 触发面：4 个入口

| 入口 | 位置 | 说明 |
|---|---|---|
| 打开页面（GET） | `app/main.py:713` | **只读请求会触发写盘** |
| 写正文 | `app/library.py:479`（`write_page(sync=True)`） | 默认就是 `True` |
| 写中间层 | `app/library.py:426`（`write_mid(sync=True)`） | 默认就是 `True` |
| 文件监听 | `app/page_watch.py:90,142` | 落盘即触发 |

### 1.4 关于风险有多大，说句实在的

我查了 `data/agent-home/logs/events.jsonl`：924 条 `sync.decide`，**全是 `ok` 分支**，`fence_drop` 零次。

但这个日志窗口只覆盖 **1 秒**（`2026-09-08T01:18:49`→`:50`，一次启动批量扫描），**得不出"危险分支从未触发"的结论**。可靠的说法是：路径一和路径二上次已用实验证明可达并确实丢数据；路径三在代码上可达，历史频率无从查证。

## 2. 为什么要改

### 2.1 根因是身份混淆，不是某个 bug

```
mid/NNNN.md 的双重身份
├── 身份 A：f(正文, 规则) 的计算结果   → 那就该能随时删掉重算
└── 身份 B：可被人/Agent 编辑的记录     → 那它就有独立信息，不能重算
```

两个身份同时成立，就必须做**双向同步**，就必然要在冲突时"仲裁"，而任何自动仲裁都是在猜。`mtime` 只是恰好被选中的那个坏判据——换成别的判据也一样，因为**冲突本身是设计造出来的，不是外部输入带来的**。

### 2.2 业界的成熟做法

学术与工程界对这个问题讨论了三十年，术语叫 **inline markup（内联标记）vs stand-off markup（旁挂标记）**，结论相当收敛：

**结论一 · 方向是不对称的**（TEI 社区的实践总结）

| 转换方向 | 可行性 |
|---|---|
| 内联 → 旁挂 | **永远可行**，无条件 |
| 旁挂 → 内联 | 仅当注解范围**互不重叠**时可行 |
| 旁挂 → 内联（有重叠） | 只能近似，需要复制内容或拆分元素 |

当前系统做的是**双向**同步，而反方向本来就不是无条件成立的——这是它注定要出问题的数学原因，不是实现没写好。

**结论二 · 主流管线的形态**：单一事实源保存**纯文本**，在**构建期**生成面向具体用途的内联版本供渲染和检索使用。也就是说，派生产物存在是合理的，但它必须是 **build 产物**，不是**记录文件**。

**结论三 · 文本不可变，注解分层**：`STAM`、W3C Web Annotation Data Model 这类现代模型都把正文当作 immutable，注解作为可 JSON 序列化的独立层，各层之间也彼此独立——这样不同来源、互相冲突的注解可以共存而不用仲裁。

### 2.3 你想加的 Obsidian 特性，恰好不需要中间文件

**这是本文档最要紧的一节。** 你当初分家的判断（"围栏会污染 AI 抽取"）是对的，但它只对**呈现指令**成立。真正该分的界线不是「原文 vs 中间文件」，而是：

| | 例子 | 该放哪 | 会不会污染 AI 抽取 |
|---|---|---|---|
| **语义标记** | `[[双链]]`、`#标签`、`^块ID`、frontmatter 属性、`> [!note]` | **原文里** | **不会**——这些正是 AI 想要的信号 |
| **呈现指令** | `::: kb-solution`、配色、图宽、同行排布 | **规则/覆盖里，按锚点索引** | 会——所以当初才分家 |

Obsidian 自己就是这个架构的活证据：**它没有中间文件**。一条笔记一个文件，双链、标签、区块 ID 全部内联在正文里；反向链接图、标签索引、区块索引都是**从正文重建的派生缓存**，放在 `.obsidian/` 下，从不手工编辑，删掉就重扫。

而且有个额外的好处：**Obsidian 的 `^block-id` 正好补上你现在缺的那个稳定锚点。** 路径三的病根是"拿整段原文当锚点"，有了块 ID 之后，呈现规则就能写成"给 `^a3f9` 这个块套解题样式"——正文怎么改，锚点都不动。

这也和仓库里已经跑通的模式一致：版式决策走 `configs/editions/<id>/layout_rules.yaml` + `overrides/pages/NNNN.yaml`，**从来不往正文里塞**。围栏这条线只是没有沿用这个已被验证的做法。

### 2.4 不改会怎样

- 每次给正文加新语法（Obsidian 或别的），都要同时改 `page_sync` 的贴回逻辑、`strip_skin` 的剥离逻辑、`sanitize_source` 的清洗逻辑——**三处手写正则必须保持语义一致**，漏一处就是静默的数据损坏。
- 路径三决定了：**正文编辑得越频繁，呈现效果掉得越多**，而且掉了没人知道。
- D1 的两条回写路径在，任何"打开页面"都带写盘副作用，排障时无法把系统当只读来推理。

## 3. 具体改哪些地方

三步，**每步都能独立验收、独立回退**。第一步不引入任何新依赖，收益最大。

### 第一步 · 中间层降级为只读派生 · **已完成**（`84f9bb8`）

实际落地与下表基本一致，两处与预案不同，都记在这里：

- **`same_prose()` 是实施中新增的**。预案没料到打标工具会重排空行——用 `same_body`
  的严口径会把"一个字没改、只多个空行"也报成冲突。新增一档只用于判定要不要报冲突，
  不参与写盘决策，口径与 `tag_chinese_layout._plain_body` 一致。
- **`library.py` 的 `sync` 默认值未改**。`_write_source()` 删掉之后 `sync_page` 已经
  不可能写正文，改默认值属于多余动作。实测 `write_page` 的所有调用方本来就传
  `sync=False`，这个默认值从未被真正走到。

验证结果见 §4.3。

原计划：

**核心动作**：删掉全部"派生层 → 源头"的写回路径，`mid` 从此只能被生成、不能被信任。

| 文件 | 位置 | 动作 |
|---|---|---|
| `app/page_sync.py` | 501-504 | **删除** `mid_dirty and not src_dirty` 的 `_write_source` 分支，改为按正文重新生成 `mid` |
| `app/page_sync.py` | 506-510 | **删除** `mtime` 仲裁整段；两边都变时一律以正文为准重生成 |
| `app/page_sync.py` | 339-344 | **删除** `_write_source()` 函数本身（删干净，杜绝再被接回去） |
| `app/library.py` | 411, 452 | `write_mid`/`write_page` 的 `sync` 默认值评估：`write_mid` 不应再触发反向同步 |
| `app/main.py` | 702-713 | GET 端点改为**只读**：缓存失效时重建 `mid`，但不写正文 |

配套：`.stamps` 的角色从"同步仲裁判据"降级为**缓存键**（正文 sha + 规则版本号）；不匹配就重建，不再有"谁赢"的问题。

**如果有人真的编辑了 `mid`**：不再静默采纳，而是**报冲突并保留两份**（`mid/NNNN.md.conflict`），由人决定。这是 §2.1 说的——冲突不该自动仲裁。

### 第三步 · 换掉手写解析器 · **已完成**（2026-09-09）

实际落地：

- **只解析、不整页 `remark-rehype`**。`unified` + `remark-parse` + `remark-directive` + `mdian` 的 `remarkOfm` 算出围栏 / 双链 / 高亮 / 注释 / callout 的原文偏移，再用现有 `paintOne` 上色。整页转 HTML 会拆掉 golden 里的 `##`、`![img](url)`。
- **方言适配**：中间层写 `::: kb-title`（冒号后有空格）；micromark 要 `:::kb-title`。`adaptDialect` 去掉那一个空格，并把 `tag()` 粘在正文上的围栏拆到单独一行。偏移映射回原文，不改磁盘上的中间层。
- **嵌套**：外层更多冒号（`:::: kb-stage` 包 `::: kb-center`）。Python `source_text.iter_top_level_fences` 用同一套冒号计数，给 `page_sync` / `sanitize_mid` 用。
- **打包**：构建期 esbuild 打成 `workspace/surfaces/page-body/lib/md-parse.bundle.mjs`（约 321 KB）。容器只读、运行时无 `node_modules`。源在 `agents/textbook-agent/parser/`，不进镜像。
- **回退**：`profile.yaml` 里 `parser: legacy` 走旧正则。
- **`wrapBareMath`**：按 `<div class="kb-*">` 配对保护，并保护双链 / 高亮 / callout 标签，避免把 `</div>`、`</a>` 当成公式。

**先做选型衡量**（按 `prefer-mature-oss` 规则，重且脆的领域不自研）：

| 需求 | 复杂度/风险 | 结论 | 推荐 | 理由 |
|---|---|---|---|---|
| `::: kb-*` 围栏解析 | **高**（嵌套、属性、边界） | **集成** | `remark-directive` (MIT) | 见下方实测：现有正则**不支持嵌套**，且这个语法本来就是它的 |
| Obsidian 语法 | **高** | **集成** | `remark-ofm` / `mdian` / `@quartz-community/remark-obsidian` | 双链/嵌入/callout/标签/块引用全覆盖，有成品 |
| Markdown → AST → HTML | **高** | **集成** | `unified` + `remark-parse` + `remark-rehype` | 事实标准，插件生态即是本方案的扩展点 |
| 数学公式 | **高** | **集成** | `remark-math` + 现有 `mathjax-full` | 顺带修掉 `%%MATH_BLOCK_n%%` 与 Obsidian 注释语法的冲突 |
| 教材独有版式规则（图宽、同行、目录识别） | 中，**业务独有** | **自研（保留现状）** | 现有 `layout_rules.yaml` | 无公认库，且已跑通 |

**实测依据**——现有围栏正则（`page_sync.py:18`、`mid_text.py:18`）在嵌套时会静默吃掉内容：

```
输入：kb-solution 里嵌一个 kb-formula，外层还有结论句
  解析出 kb-solution  内容='解法一：⏎'
  共识别 1 个块
  '因此得证。' 有没有落进任何一个块: False      ← 外层正文被吞
```

原因是 `([\s\S]*?)` 非贪婪匹配遇到第一个 `:::` 就收尾。`remark-directive` 用冒号数量区分层级（`::::` 包 `:::`），本来就解决了这个问题。

**部署约束与解法**：渲染端 Node 18.20.4，容器只读且**没有 `node_modules`**（现状是零依赖手写，`tag.mjs` 里 24 处正则替换）。所以不能直接 `npm i`。
解法：**构建期用 esbuild 打成单文件 `.mjs` 随镜像分发**，放在 `prepare.mjs` 旁边。这样既拿到成熟解析器，又保留 surfaces 目录"改文件即生效、可热替换"的现有特性。

## 4. 改完的影响

### 4.1 影响面

| 对象 | 影响 |
|---|---|
| `pages/*.md`（正文） | 第一步后只有人和导入流水线能改正文；第二步由 stamp 工具追加 ` ^kb-xxxxxx`，不改正文词句 |
| `mid/*.md` | 围栏内同步同一份标记；仍不能反向覆盖正文 |
| AI 抽取 / RAG | 读 `pages/` 时会看到行尾 ` ^kb-xxxxxx`，是可识别元数据 |
| 前端渲染 | `prepared` 里不出现 `^kb-`（已对拍：正文有标记，画面没有） |
| Agent 编辑中间层的能力 | 仍收窄为冲突留档 |
| 导入流水线 | 新书/新围栏需再跑 `stamp_block_ids(apply=fix)` |

### 4.2 回退路径

- 第一步：纯删代码，`git revert` 即可；`.stamps` 格式不变，向后兼容。
- 第二步：代码 `git revert`；正文回退用 `/tmp/kb-block-id-backup-20260908` 覆盖 `textbooks/*/pages` 与 `mid`（目录属 root，需容器内或 root 权限）。留下 ID 也不影响解析。
- 第三步：新解析器打包成独立 `.mjs`，`profile.yaml` 里切回旧 `prepare.mjs` 即回退；`.last-good` 机制本来就是为此存在的。
